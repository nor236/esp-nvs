# esp-hal 1.2.0 及依赖同步升级 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 esp-nvs workspace 的 `esp-hal` 升级到 `1.2.0`（caret，解析到最新 `1.2.x`），同步升级全部 esp-rs 生态依赖与第三方依赖，并处理由此带来的 MSRV 1.95.0 与 feature 结构变化。

**Architecture:** 依赖版本声明集中在三个 crate 的 `Cargo.toml` 与 `Cargo.lock`。真正的代码适配点只有两处，都在 feature/配置层而非 Rust 源码：
1. `esp-storage` 0.10.0 把 `embedded-storage` trait 实现改成 opt-in feature，esp-nvs 的 `Platform: NorFlash` 依赖它，必须为每个 chip feature 启用 `esp-storage/embedded-storage`。
2. `esp-alloc` 0.11.0 要求显式 chip feature，example 必须为每个 chip 补上 `esp-alloc/<chip>`。
其余 API（`esp_hal::rom::crc::crc32_le`、`esp_hal::main`、`esp_hal::time`、`esp_hal::Config`、`esp_hal::init`、`esp_hal::ram(reclaimed)`、`FlashStorage::new`、`esp_app_desc!`、`heap_allocator!`）在 1.2.x / 0.10.0 / 0.11.0 中仍然存在，无需改代码。

**Tech Stack:** Rust edition 2024；`esp-hal` 1.2.x、`esp-storage` 0.10.0、`esp-bootloader-esp-idf` 0.6.0、`esp-alloc` 0.11.0、`esp-backtrace` 0.20.0、`esp-println` 0.18.0；第三方 `base64` 0.23.1、`clap` 4.6.7、`serde` 1.0.229、`thiserror` 2.0.21、`similar` 3.2.0、`tempfile` 3.27.0、`defmt` 1.1.1、`embedded-storage` 0.3.2、`log` 0.4.34、`cfg-if` 1.0.5。

**Spec:** 用户请求“esp-hal 升级至 1.2.0 及依赖同步升级”，并确认：(a) esp-hal 约束写 `1.2.0` 自动取最新 1.2.x；(b) 升级范围为 esp 生态 + 所有第三方依赖升到最新。版本事实来自 crates.io API 与各 crate 的 `CHANGELOG.md`（esp-rs/esp-hal 对应 tag）。

## Global Constraints

- esp-hal 依赖约束写 `"1.2.0"`（caret），不写 `=1.2.0`，不写 `1.2.2`。
- 所有 esp-rs 生态 crate 使用配套版本：`esp-storage = "0.10.0"`、`esp-bootloader-esp-idf = "0.6.0"`、`esp-alloc = "0.11.0"`、`esp-backtrace = "0.20.0"`、`esp-println = "0.18.0"`。
- 第三方依赖各取最新稳定版（见上方 Tech Stack）。
- MSRV 由 esp-rs 1.2 系列的 `rust-version = "1.95.0"` 决定；本机为 Rust 1.96.0，满足要求。
- 不修改任何公开 API、算法或业务逻辑；不调整 crate 自身 `version`（仍为 0.5.0）。
- 新增/修改配置不使用 pom profile 类机制；不做与升级无关的重构。
- 仅允许改动本仓库目录内文件。
- 已是最新、保持不动的依赖：`strum 0.28.0`、`csv 1.4.0`、`hex 0.4.3`、`pretty_assertions 1.4.1`、`critical-section 1.2.0`。

## Review Focus

- **host 测试安全边界**：`esp-nvs` 的手测通过 `MemFlash` 实现，不依赖 esp 生态；升级不得改变 `cargo test --workspace --all-targets` 的结果。
- **esp-storage / embedded-storage feature 遗漏**：遗漏时 `NorFlash` 未对 `FlashStorage` 实现，任何带 chip feature 的 `esp-nvs` 构建都会在 `Platform` 约束处报错。必须在全部 9 个 chip feature 上启用。
- **esp-alloc / chip feature 遗漏**：`esp-alloc` 0.11.0 声明 chip selector 为 mandatory，遗漏时 example 构建失败（esp-config/build script 报错）。
- **锁文件一致性**：CI 的 `test.yml` 使用 `cargo test --locked`，必须提交更新后的 `Cargo.lock`，否则 CI 失败。
- **文档与事实漂移**：`README.md`、`AGENTS.md`、CI msrv 矩阵中的旧版本号（`0.8.1`、`1.88.0`、`1.93.1`）若未更新，会误导使用者触发无效 feature（`low-level` 已不存在）。
